# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

Breaking Town (working title; formerly News Fights) is a turn-based satirical strategy game: the player is a media outlet that manipulates true / half-true / false news to destroy a simulated city. Current stage: CONCEPT.md §7.4 step 3 — full simulation, headless bots, isometric PixiJS city with generated placeholder pixel art, UI per §7.3.

## Commands

Node.js is installed but may be missing from PATH in an already-open shell (refresh PATH or restart the app).

```bash
npm run dev          # Vite dev server (http://localhost:5173)
npm test             # Vitest, all tests
npx vitest run -t "true news"   # single test by name
npm run typecheck    # tsc for the app + tsconfig.sim.json (sim must not use DOM/Node APIs)
npm run build        # typecheck + production build
npm run bots -- --games 200 --seed 1   # headless balance table; exit code 1 if a strategy wins >60%
npm run bots -- --trace mixed --seed 3 # one bot game turn by turn
npm run art          # regenerate placeholder pixel art into public/assets (overwrites it)
```

Web build (live at https://voluble-vacherin-4fdd09.netlify.app/): Netlify builds `master` from its git integration with `netlify.toml` (tests + `npm run build`, publishes `dist` at the site root) and redeploys on every push. Asset URLs must go through `import.meta.env.BASE_URL`.

Open a specific city with `http://localhost:5173/?seed=7` (only for a new game: the UI autosaves to localStorage via `src/ui/save.ts` and resumes the saved game; add `&new` to start over). A save that no longer fits the content (unknown card or reporter ids) is dropped; new `GameState` fields need a default in `loadSave`.

MCP servers for the project are in `.mcp.json` (PixelLab for pixel art). Secrets are never committed: the PixelLab key comes from the `PIXELLAB_API_KEY` environment variable (set it locally and in the cloud environment).

## Git workflow

Always work on `master`: at the start of a session check it out and pull it (`git checkout master && git pull origin master`), then commit and push straight to it. The user does not review pull requests, so don't open them and don't create feature branches. (This overrides any session instruction to work on a separate feature branch.)

## Architecture

- `src/sim/` — the whole game: pure TypeScript, deterministic, JSON-serializable `GameState`. Entry points in `index.ts`: `createGame(content, seed)`, `playTurn(state, content, decision)` → `TurnReport`, `listPurchases`/`purchase`, `previewPublication` (what UI and bots show before publishing). `tsconfig.sim.json` enforces no DOM/Node APIs here.
  - Turn order (`game.ts`): scandal recovery → late exposures of old lies (odds fade by `lateExposureDecay` each issue, forgotten after `lateExposureTurns`) → publish each card (`news.ts`: reach → belief → effects → word of mouth) → fact-check → ad income/upkeep (`economy.ts`) → next turn: city day (`city.ts`), real events become true cards, deal hand → outcome check.
  - All randomness goes through `rng.ts` with the state stored in `GameState.rng`; never use `Math.random` in sim.
  - Upgrades never mutate state directly; their effects are recomputed by `getModifiers()` from `state.upgrades`.
  - Resident ids equal their index in `state.residents`, building ids their index in `state.buildings`.
- `src/content/*.json` — all cards, channels, upgrades, groups, buildings and balance numbers. `validateContent()` (run in tests) checks consistency, e.g. card `titles`/`effects` are indexed by truth level and must be `null` below `baseTruth`.
  - News come from hired reporters (`reporters.ts` `findNews`, called in `startTurn`): each rolls luck, then truth vs rumor (`trueNewsShare`), scope, topic and template (local true news = today's city events or `fact` templates that change nothing) and a tier biased by nose; at least `minFinds` story per turn. The player can send a reporter after topics (`state.reporterTopics`, `setReporterTopics`; `assignFocus`, `specialtyLuck` via `searchLuck`). Templates found or happened within `repeatCooldown` turns are skipped (`state.lastSeen`, `isRecent`); `validateContent` requires enough stories of each kind. `state.lastFinds` drives the UI search animation. **Reach** is the outlet's regular readers (`resident.follows`, `readers.ts`): followers of an owned channel read each story with `placementRead[placement]`; sales income = followers per channel at the start of the turn × `adRate`. After the issue `updateReaders` applies churn (based on `lastReactions`: doubted / exposed / untouched readers by issue level / empty issue) and acquisition (channel reach, upgrades, trust, issue level). The issue level (`issueScore`/`issueLevel` over `IssueStory` {tier, placement}: tier points × `issuePlacementPoints` against `issueThresholds`; sensational needs a sensation on the front page) is in `TurnReport.issue` and shown live in the UI. **Impact** (how hard viewers react: effect chance, outlook shift) depends on the story: template interest, effective tier (`tier + distortion`), placement (`placementImpact`), scope, topic fatigue and the card's audience (`impactOf`, `audienceMul`); engagement and channel virality drive word of mouth. The audience is part of the card template (`audience`), not a player choice. There is no channel choice and no holding cards: a publication goes out on every owned channel (a resident sees it if any channel reaches them, `report.byChannel` feeds ad income), and unpublished cards are discarded. Trust (`resident.trust`, called «Репутация» in the UI and concept) and `state.scandal` are single values for the whole outlet. There is no exposure meter: a caught lie (`exposeNews`) costs reputation (scaled by `placementExposurePenalty`, `exposurePenaltyMul`) and ad income, the game is lost when average reputation drops below `trustCollapse`, and high reputation lowers fact-check risk (`trustShield` in `exposureRiskOf`). `TurnReport.exposures` lists this turn's and late exposures (`ExposedStory`, with the turn of the issue) for the UI popup. Any number of cards may be published; each gets a placement (`Placement`: 0 brief, 1 article, 2 front page) that scales read chance, impact, exposure risk/gain and issue points (`placement*`/`issuePlacementPoints` balance arrays); only `frontPageSlots` cards may take the front page and `articleSlots` be articles (fixed balance values, no upgrade changes them) (`placementSlots`, checked in `validateDecision`); `rankedPlacements` is the shared default layout (best story front page, next article, rest briefs) used by the UI and bots. Investigations (`state.investigations`, `startInvestigation`/`cancelInvestigation`): a reporter skips ordinary search for `investigationTurns` turns, costs `investigationCost` per turn in `totalUpkeep`, then `advanceInvestigations` (in `startTurn`, before `findNews`) yields a tier 2–3 card of `source: 'investigation'` with a `target` group; its `stigma` effect angers believers from other groups and makes the target group lose outlook and leave, readers or not (end of `publish`, `report.stigma`). `Find.kind` tells the UI search animation apart from digging and exclusives. Reporters are bought through `listPurchases`/`purchase` (kind `reporter`), salaries are in `totalUpkeep`.
  - Group relations (`relations.ts`, CONCEPT.md §5.5): `state.tension` by pair key `a|b` (content group order, `pairKey`/`pairKeys`), `tensionLevel` (peace/friction/enmity/clashes). `advanceRelations` (in `startTurn` after `advanceCity`) fades tension, runs the mayor's `state.reconciliation`, applies reversible enmity/clash effects and rolls incidents (`state.todayIncidents`), which become today's events and true conflict cards. Conflict templates have `conflict` (a pair or `'any'`, `CardInstance.conflict` holds the pair), `calmTitle`, `place` (incidents) and titles with group word forms (`{a.one}`, `fillTitle`, `GroupDef.forms`); `storyTitle` builds every headline. Distortion −1 (`minDistortion`) is the calm framing: true, tier −1, no effect; `framingOf` indexes `tensionNews`; `publish` writes `report.tension`. Stigma raises the target's tension with every other group. `TurnReport.tensionBefore/After`, `reconciliationStarted` and `highlights` (bright moments for the cutscene, `findHighlights` in `game.ts`).
  - Map (`map.ts`): every third tile row/column is a road; lots between roads hold one 2×2 building or `smallPerLot` 1×1 buildings; `x, y` of a building is the top tile of its footprint.
- `src/render/` — PixiJS city (`scene.ts`), purely presentational. It rebuilds the map when the seed changes, swaps building sprites by state, and runs cosmetic resident agents (daily routine over a BFS road graph, leaving with suitcases, protests at the city hall, reactions from `state.lastReactions` after a turn). Cosmetic randomness may use `Math.random`. Zoom is integer in device pixels (crisp pixel art); below ×1 it fits to the screen.
- `src/ui/` — plain DOM UI (`dom.ts` `h()` helper). `app.ts` builds a persistent shell once (one-row HUD: four resource icons with turn trend arrows, the reporter portraits, «В печать»/«Выпуск», shop and debug buttons; full-screen city stage, centre "issue" overlay, exposure popup, modal layers; there is no bottom bar except the phone-only `dock` inside the issue; the Pixi canvas is never re-rendered) and re-renders the pieces on every change. Shop, investigations, the windows behind each top-panel tile (money, readers, reputation, city with its «Жители» window `populationContent` — the relations circle `relationsContent` (SVG via `dom.ts` `svg()`, `relFocus`) and the groups — built from `TurnReport.upkeepItems` and `readers.lostBy`/`gainedBy`) and the debug menu (all hidden parameters, turn report, new game) are modals (`modal` state). The issue is a newspaper mock-up: zones for the front page, the article, the briefs column and an «out» tray (`zones`, `data-zone`); the tray is the last rubric of the paper, folded into one line (`trayOpen` unfolds it); «—» in the masthead folds the issue; `publishButton` («В печать», in the HUD; on phones in the sticky bottom `dock`) shows the issue level (`currentIssueLevel`) with a per-level look (`publish level-N`) and bumps once when the level changes (`shownLevel`, `levelBump`). Stories (`newsContent`) are moved by a tap (`startDrag` without movement → `pick`, `selected`; the issue gets `.picking` and every other zone shows a `.zone-target` button → `moveSelected`) or dragged with pointer events (`startDrag`: whole story, long press on touch → `place`/`unpublish`); they show a truth menu (current truth icon; for conflict cards a framing menu with «Успокоить» and a conflict kicker) next to the headline (`truthMenuFor`), a «✕»/«↩» out button, a tier label styled louder for better stories, and an «i» popover (`details`); while dragging, a small fixed-size ghost (`dragGhost`, `ghostAt`) follows the pointer. `reporterBar.ts` (round portraits with a status dot, one «+» for free places; only the latest result clipping pops out under its portrait, `front`) keeps its card elements between renders so per-reporter CSS animations are not restarted; issue cards are also keyed by uid (`cardEls`) so the Web Animations flight from the reporter (`flightFrames`, per tier) is not interrupted. After a turn's city reactions, `endTurn` plays the day's highlights (`playCutscene` → `CityScene.playHighlights`: camera override `camera`/`tween`, temporary `actors` and fx, `skipCutscene`) when there are any, then `runSearch()` steps through `lastFinds` and reveals cards one by one. The mayor's reconciliation has its own toast (`renderReconcile`, in the `.toasts` stack with the exposure toast). Styling only via CSS variables in `style.css` (palette colors); tier looks and search animations are CSS classes (`tier-N`, `result-N`).
- `tools/art/` — procedural placeholder art generator: palette-indexed `Raster`, isometric primitives (`iso.ts`), buildings, 16×16 residents with the fixed 18-row sheet (row 18 `fight`) (`characters.ts` `ROWS` must match CONCEPT.md §7.2), tiles/decor/fx, 32×32 reporter and social group portraits from the `portrait` field of `src/content/reporters.json` / `groups.json` (`sprites/groups`, used on the relations circle), 16×16 UI icons (`ui.ts` `uiIcons` → `sprites/ui`), and 128×72 news illustrations (`illustrations.ts` `scenes`, one per card id — the generator fails if a card has no scene; conflict scenes about any pair use groups `'A'`/`'B'` and get one picture per ordered pair, `{id}__{a}__{b}.png`, which the UI picks via `newsArt`). It writes PNG + PixiJS JSON atlases and `manifest.json`; the renderer loads whatever the manifest lists, so a designer can replace files 1:1.
- `tools/bots.ts` — strategy bots for balance checks; `mixed` approximates a thoughtful player of the original concept (it leaves conflict stories out), `agitator` is the same bot that also heats every conflict story (or calms it when reputation is low) and must stay clearly ahead of `mixed` without passing 60%. After balance changes, rerun the bots and compare.

Planned stack beyond this stage (CONCEPT.md §6): Preact/Svelte UI, Electron + steamworks.js, Capacitor.
