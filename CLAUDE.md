# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

Breaking Town (working title; formerly News Fights) is a turn-based satirical strategy game: the player is a media outlet that manipulates true / half-true / false news to destroy a simulated city. Current stage: CONCEPT.md §7.4 step 3 — full simulation, headless bots, isometric PixiJS city with generated placeholder pixel art, UI per §7.3.

## Commands

Node.js is installed but may be missing from PATH in an already-open shell (refresh PATH or restart the app).

```bash
npm run dev          # Vite dev server (http://localhost:5173)
npm test             # Vitest, all tests
npx vitest run -t "true news"   # single test by name
npm run typecheck    # tsc for the app + tsconfig.sim.json (sim must not use DOM/Node APIs)
npm run build        # typecheck + production build
npm run bots -- --games 200 --seed 1   # headless balance table; exit code 1 if a strategy wins >60%
npm run bots -- --trace mixed --seed 3 # one bot game turn by turn
npm run bots -- --games 200 --mode save # the save mode's strategies (CONCEPT.md §8)
npm run bots -- --games 200 --difficulty hard # any mode at a difficulty level (CONCEPT.md §4.6)
npm run bots -- --games 200 --mode save --set saveLoseIndex=71 --set 'rivalStartTurn={"destroy":7,"save":2}'  # try balance values (JSON) without editing balance.json
npm run bots -- --games 200 --twist election  # every game gets only this mid-game twist (CONCEPT.md §4.9)
npm run art          # regenerate placeholder pixel art into public/assets (overwrites it)
```

Web build: GitHub Pages, deployed by `.github/workflows/pages.yml` on every push to `master` as one site with two builds. The **beta** for testers, https://lightvdv.github.io/breaking_town/, is built from the commit in `.github/beta-commit` and does not change on pushes; the user gave it to beta testers, so move it (put a new hash there and push) only when the user asks to update the beta. The **dev preview**, https://lightvdv.github.io/breaking_town/dev/, is master after the tests (`--base=/<repo>/dev/`). Both share an origin, so the dev build keeps its save and settings under keys with `STORAGE_SUFFIX` (`src/assets.ts`, `-dev`). The site lives under `/breaking_town/`, so asset URLs must go through `ASSET_BASE` (`src/assets.ts`): a build (`vite.config.ts`, plugin `versioned-assets`) copies `public/assets` into `dist/assets/v<build>/` so browsers never keep stale art after a deploy; the dev server serves `/assets/` as is. The old Netlify site (https://voluble-vacherin-4fdd09.netlify.app/, `netlify.toml`, site root) is paused: the team ran out of build credits.

Open a specific city with `http://localhost:5173/?seed=7` (only for a new game: the UI autosaves to localStorage via `src/ui/save.ts` and resumes the saved game; add `&new` to start over, skipping the title screen). `?debug` adds «Отладка» to the pause menu; `&mode=save` makes a new game from the address a save-mode one. Player settings (fast search, no cutscenes, intro seen, difficulty, rival plaque open; the game has only the dark look) live apart from the save (`src/ui/settings.ts`). Nothing is saved until a turn has been played (`saveNow` checks `hasGame` and `state.turn > 1`; a loaded save with `turn ≤ 1` is not offered to continue). The opening story plays before every new game for now (`startGame` → `watchIntro`). A save that no longer fits the content (unknown card or reporter ids) is dropped; new `GameState` fields need a default in `loadSave`.

MCP servers for the project are in `.mcp.json` (PixelLab for pixel art). Secrets are never committed: the PixelLab key comes from the `PIXELLAB_API_KEY` environment variable (set it locally and in the cloud environment).

## Git workflow

Always work on `master`: at the start of a session check it out and pull it (`git checkout master && git pull origin master`), then commit and push straight to it. The user does not review pull requests, so don't open them and don't create feature branches. (This overrides any session instruction to work on a separate feature branch.)

## Source of truth

[CONCEPT.md](CONCEPT.md) (in Russian) is the authoritative spec and is meant to drive code, content and art generation. Read it before implementing anything. Its rules are mandatory unless the user says otherwise; numbers marked «стартовые» are initial balance values and belong in JSON, not code. Keep CONCEPT.md updated when the user changes the design — it should describe the game only (no market analysis or other side material).

The user communicates in Russian; UI text and content are in Russian, code identifiers and comments in English.

Never edit files through PowerShell `Get-Content`/`Set-Content` pipelines: Windows PowerShell 5.1 corrupts UTF-8 Cyrillic. Use the Edit/Write tools.

## Architecture

- `src/sim/` — the whole game: pure TypeScript, deterministic, JSON-serializable `GameState`. Entry points in `index.ts`: `createGame(content, seed)`, `playTurn(state, content, decision)` → `TurnReport`, `listPurchases`/`purchase`, `previewPublication` (what UI and bots show before publishing). `tsconfig.sim.json` enforces no DOM/Node APIs here.
  - Turn order (`game.ts`): scandal recovery → late exposures of old lies (odds fade by `lateExposureDecay` each issue, forgotten after `lateExposureTurns`) → publish each card (`news.ts`: reach → belief → effects → word of mouth) → fact-check → ad income/upkeep (`economy.ts`) → next turn: city day (`city.ts`), real events become true cards, deal hand → outcome check.
  - All randomness goes through `rng.ts` with the state stored in `GameState.rng`; never use `Math.random` in sim.
  - Upgrades never mutate state directly; their effects are recomputed by `getModifiers()` from `state.upgrades`.
  - Resident ids equal their index in `state.residents`, building ids their index in `state.buildings`.
- `src/content/*.json` — all cards, channels, upgrades, groups, buildings and balance numbers. `validateContent()` (run in tests) checks consistency, e.g. card `titles`/`effects` are indexed by truth level and must be `null` below `baseTruth`.
  - News come from hired reporters (`reporters.ts` `findNews`, called in `startTurn`): every event of the day (`generateEvents` plus incidents) is always written up first, by the reporter on its topic or in turn (an extra `Find`); then each reporter rolls luck, then truth vs rumor (`trueNewsShare`), scope, topic and template (local true news = `fact` templates that change nothing) and a tier biased by nose within the template's `tiers` range (so the headline fits its level); a story whose template `requires` a building type is bound to one open building of it (`CardInstance.building`, names from `BuildingDef.names`, `buildingName`, shown as a kicker); at least `minFinds` story per turn. The player can send a reporter after topics (`state.reporterTopics`, `setReporterTopics`; `assignFocus`, `specialtyLuck` via `searchLuck`). Templates found or happened within `repeatCooldown` turns are skipped (`state.lastSeen`, `isRecent`); `validateContent` requires enough stories of each kind. `state.lastFinds` drives the UI search animation. **Reach** is the outlet's regular readers (`resident.follows`, `readers.ts`): followers of an owned channel read each story with `placementRead[placement]`; sales income = followers per channel at the start of the turn × (`prices[state.price]` + `adRate` + kiosks) (`incomePerReader`, `setPrice`; the price is chosen in the masthead's second row by a chip and menu without numbers, `renderPrice`, `priceMenuOpen`, `priceLabels`, coin icons `sprites/ui/price_0..3`). Who buys depends on the price and the resident's wealth class (`wealthOf`: working / pensioner / jobless, `priceBuy`, `buyWillingness`): it scales joining, and a reader who cannot or grudges to pay churns with reason `price`. After the issue `updateReaders` applies churn (based on `lastReactions`: doubted / exposed / untouched readers by issue level / empty issue) and acquisition (channel reach, upgrades, trust, issue level). The issue level (`issueScore`/`issueLevel` over `IssueStory` {tier, placement}: tier points × `issuePlacementPoints` against `issueThresholds`; sensational needs a sensation on the front page) is in `TurnReport.issue` and shown live in the UI. **Impact** (how hard viewers react: effect chance, outlook shift) depends on the story: template interest, effective tier (`tier + distortion`), placement (`placementImpact`), scope, topic fatigue and the card's audience (`impactOf`, `audienceMul`); engagement and channel virality drive word of mouth. The audience is part of the card template (`audience`), not a player choice. There is no channel choice and no holding cards: a publication goes out on every owned channel (a resident sees it if any channel reaches them, `report.byChannel` feeds ad income), and unpublished cards are discarded. Trust (`resident.trust`, called «Репутация» in the UI and concept) and `state.scandal` are single values for the whole outlet. There is no exposure meter: a caught lie (`exposeNews`) costs reputation (scaled by `placementExposurePenalty`, `exposurePenaltyMul`) and ad income, the game is lost when average reputation drops below `trustCollapse`, and high reputation lowers fact-check risk (`trustShield` in `exposureRiskOf`). `TurnReport.exposures` lists this turn's and late exposures (`ExposedStory`, with the turn of the issue) for the UI popup. Any number of cards may be published; each gets a placement (`Placement`: 0 brief, 1 article, 2 front page) that scales read chance, impact, exposure risk/gain and issue points (`placement*`/`issuePlacementPoints` balance arrays); only `frontPageSlots` cards may take the front page and `articleSlots` be articles (fixed balance values, no upgrade changes them) (`placementSlots`, checked in `validateDecision`); `rankedPlacements` is the shared default layout (best story front page, next article, rest briefs) used by the UI and bots. Investigations (`state.investigations`, `startInvestigation`/`cancelInvestigation`): a reporter skips ordinary search for `investigationTurns` turns, costs `investigationCost` per turn in `totalUpkeep`, then `advanceInvestigations` (in `startTurn`, before `findNews`) yields a tier 2–3 card of `source: 'investigation'` with a `target` group; its `stigma` effect angers believers from other groups and makes the target group lose outlook and leave, readers or not (end of `publish`, `report.stigma`). `Find.kind` tells the UI search animation apart from digging and exclusives. Reporters (up to `maxReporters` = 5 of 14) are hired through the HR agency: `callAgency` is free for the first search a turn and costs `agencyFee` after (`agencyCost`, `state.agencyCalls` reset in `startTurn`) and puts 1–`agencyMaxOffer` random unhired reporters (by `ReporterDef.weight`, 0 = never offered) into `state.agencyOffer` (cleared in `startTurn`), `hireFromAgency` hires one of them for its `hireCost`; salaries are in `totalUpkeep`. At most `maxSensations` (1) sensation: extra tier-3 finds are lowered to tier 2 in `startTurn`, `validateDecision` rejects an issue with two effective sensations, and `limitSensations` tones extras down (UI `fitSensations`, bots).
  - The outlet is a newspaper only (`channels.json` holds just `newspaper`; the channel code stays generic). Upgrades (`upgrades.json`, `section` for the window heading, `series` for chains such as `kiosk_1..4`) can add reach, sales per reader (`adRateAdd`, `adRateOf`), upkeep (`upkeepAdd`), group affinity (`groupReach`) and lower churn (`churnMul`); `loadSave` drops channels and upgrades that no longer exist.
  - Group relations (`relations.ts`, CONCEPT.md §5.5): `state.tension` by pair key `a|b` (content group order, `pairKey`/`pairKeys`), `tensionLevel` (peace/friction/enmity/clashes). `advanceRelations` (in `startTurn` after `advanceCity`) fades tension, runs the mayor's `state.reconciliation`, applies reversible enmity/clash effects and rolls incidents (`state.todayIncidents`), which become today's events and true conflict cards. Conflict templates have `conflict` (a pair or `'any'`, `CardInstance.conflict` holds the pair), `calmTitle`, `place` (incidents) and titles with group word forms (`{a.one}`, `fillTitle`, `GroupDef.forms`); `storyTitle` builds every headline. Distortion −1 (`minDistortion`) is the calm framing: true, tier −1, no effect. Bad true stories with `softTitles`/`softEffects` (`CardInstance.soft`) can be soothed to −1 «Без паники» (half-truth) and −2 «Всё хорошо!» (lie): `cardTruth` gives 1/2, the tier drops, `isSoothed`; the menu labels every step by tone (`toneOf`, `toneLabels`, `soothingLabels` in `ui/text.ts`) and lists only the steps the story has; `framingOf` indexes `tensionNews`; `publish` writes `report.tension`. Stigma raises the target's tension with every other group like a heated conflict (`tensionStigma` × impact × believers' share among other readers). `TurnReport.tensionBefore/After`, `reconciliationStarted` and `highlights` (bright moments for the cutscene, `findHighlights` in `game.ts`).
  - Residents rarely leave (`leaveScale` multiplies every leave chance). Order (`computeMetrics`) falls with protesters, residents afraid of crime (`fearTurns`, effect `fear` of crime stories: they stay at home, skip bars and often shops; the renderer sends them home) and the jobless (`joblessCrime`); the UI calls it «Порядок и безопасность».
  - Rival papers (`rival.ts`, `state.rival`, CONCEPT.md §8): every game has one, `RivalState.kind` by mode (`rivalKindOf`): the tabloid «Вечерний Набат» in the save mode, the guardian «Голос города» in the destroy mode (good news, bad events soothed, `guardianStoriesMax`; closing it wins the destroy mode too). Both answer our recent lies (`state.ourPrinted`, `recordOurIssue`, `counterTargets`: the tabloid our soothing ones, the guardian our scary ones; ≤ `rivalCountersMax` a day on top of its issue, templates `tabloid_debunk`/`guardian_debunk`, a believed one costs us `rivalDebunkTrust`); our debunks of them use `debunk`/`debunk_guardian` (`RIVAL_TEMPLATES`). UI names via `rivalNames` (`ui/text.ts`). Save mode (`GameState.mode` `'save'`, `createGame(c, seed, mode)`): `planRival` (in `startTurn`, hidden) picks 1–`rivalStoriesMax` frightening stories (today's bad events first), places and distorts them (lies while trusted); `publishRival` prints them in `playTurn` after our issue through the same `publish` (option `rival`: `r.rivalReader`, `r.rivalTrust`, no upgrades via `modifiersOf(c, [])`) and records them in `rival.printed` (kept `debunkWindow` days, `pruneRival`). Debunks: `findNews` `make` turns a find into a `debunk` card (template `debunk`, `makeDebunk`, `CardInstance.debunk` {uid, title, effect}, base truth = 2 − the story's truth) for a recent half-truth or lie not yet debunked or exposed (`debunkTargets`) — with `assignFocus` for reporters in `state.rivalWatch` (`setRivalWatch`, toggle in the reporter window), `debunkFindChance` for the others. A believed debunk (in `publish`) removes the belief in the rival story, restores outlook, ends its fear/protest and lowers `rivalTrust` (`report.effects.debunk`, `TurnReport.rival.cured`); `markDebunked`. `verifyRival` fact-checks it (`printed.exposed`), `updateRivalReaders` moves its readers and closes it (`rivalCloseShare`, `rivalTrustCollapse`). `checkOutcome` in save mode: `rivalClosed` / `citySaved` (turn limit reached) wins, `cityFallen` (`saveLoseIndex`) loses. UI: mode cards in the `newgame` modal, the rival plaque above the paper with its last days' stories (`rivalNotice`, `renderRival`), the debunk kicker, per-mode intro (`introSlides(c, mode)`, `settings.introSeenSave`, art `rival`/`defend`/`saved`). Bots: `npm run bots -- --mode save` (`defender`, `liarDefender`, `soother`, `bystander`, `destroyer`).
  - Story arcs (`arcs.ts`, `arcs.json`, CONCEPT.md §3.1а): an arc is three stage templates and two endings in `cards.json` (`arc`, `arcStage`; never in ordinary search, events or the rival's pool). `advanceArcs` (in `startTurn` after `generateEvents`) starts one (`arcChance`, `arcsMax`, `arcStartTurn`, each once per game: `state.arcs`, `state.arcsDone`), pushes the next stage into today's events and, after the third, picks the ending by `arcLean` (pressure + `arcMoodBias` × (`arcMoodPivot` − mood)) and applies its `cityEffect`. `pushArc` adds distortion × `arcPlacementWeight[placement]` for our published stages and the rival's (`rivalArcChance`, extra on top of its stories). UI: `arcInfo` → the «Сюжет · … · день N из 4» kicker (`arc-kicker arc-bad/arc-good`) and the lean line in «i».
  - Offers with a catch (`offers.ts`, `offers.json`, CONCEPT.md §3.5а): `advanceOffers` (in `startTurn`) ends finished deals and may put one offer in `state.offer` (`offerChance`, `offerStartTurn`, `offerCooldown`, `lastOfferTurn`; `mode`/`requires` filter); it lapses with the turn. `answerOffer`: silence pays `amount` at once, subsidy pays daily, both go to `state.deals`; kompromat puts a tier-3 `source: 'offer'` card in the hand with hidden `CardInstance.setup` (`setupChance`): `verifyNews` checks it as a lie and `exposeNews` multiplies the penalty by `setupPenaltyMul` (`ExposedStory.setup`). `settleDeals` (in `playTurn` before income): `dealBrokenBy` (harmful `storyEffect` about the silenced building / subsidy topic) costs `penalty` and `trustPenalty`; subsidies pay and drain trust (`TurnReport.deals`). UI: `renderOffer` plaque (`notice-offer`, icon `ui/offer`), `deal-kicker`/`offer-kicker`, deal lines in the money window. Bots: `answerOffers`.
  - Reporters with character (`staff.ts`, CONCEPT.md §3.3б): `state.staff` {xp, loyalty} per reporter (`staffOf` creates it lazily, `hireFromAgency` resets it). `skilledReporter` adds `levelLuck[level]`/`levelNose[level]` (arrays by level; `levelOf`, `reporterLevels` 0/40/170/500: Master ≈ one full game, Legend only across a campaign), and `reporterCheckMul` (`levelCheckMul`) lowers the fact-check risk of a master's or legend's stories in `verifyNews` and `previewPublication` and is what `findNews` and `skillLine` use. `updateStaff` (in `playTurn` after `recordOurIssue`): xp by `xpPerPlacement`; outright lies cost `lieLoyalty` × `ReporterDef.honesty`; untrue scary stories on a reporter's `tie.topic` cost `tieLoyalty`; below `quitLoyalty` they quit (`removeReporter`, the last one stays) and may leak (`leakChance`: their `pendingLies` are exposed, `ExposedStory.leaked`). Poaching is an offer of kind `poach` (`poachTarget` first in `advanceOffers`; keep for `retainCost`, decline or lapse → `defect`). `TurnReport.staff` feeds the «Редакция» plaque (`renderStaff`, folded to one line unless `settings.staffOpen`) and the promotion flash on the portrait (`ReporterBar.celebrate`, once per turn after the search, `promotedTurn`); the reporter window's head is `reporterHead` (big portrait, `level-chip` + `level-pips`, `xp-bar`, `xp-caption` with `levelNamesGen`; corner `rep-corner`: `skill-icon` luck/nose icons `ui/luck_0..3`, `ui/nose_0..3` by `skillTiers`, tips by hover or `openInfo` 'luck'/'nose', closed by a press elsewhere; `loyaltyOf` word; `aboutLine` behind «i») and its explanations sit behind «i» buttons on the section headings (`infoSection`, `openInfo`); `characterLine` in the team window; `ReporterDef.female` picks Russian verb forms.
  - Named residents (`people.ts`, `people.json`, `letters.json`, CONCEPT.md §2.2а): `assignPeople` (in `createGame`) binds each person to a resident of their group (`state.people`, person id → resident id; preferably at `job`). `playTurn` takes `snapshotPeople` at the start and calls `updatePeople` after `startTurn`: changes go to `state.fates` (`FateEvent`, kept `fatesKept`), and `state.letters` (≤ `lettersMax`, templates with `{title}` and `{женская|мужская}` forms; anonymous with `anonymousLetterChance`) are today's «Письма читателей» (UI `renderLetters`, `lettersBox` in the paper; «Горожане» in the residents window, `peopleContent`, `fateText`). Portraits: `sprites/people/{id}.png` from `portrait`.
  - Difficulty (`difficulty.ts`, `difficulties.json`, CONCEPT.md §4.6): `withDifficulty(c, difficulty, mode)` merges a level's `balance` and `modes[mode]` overrides; the sim always gets the adjusted content and `GameState.difficulty` remembers the level. The UI keeps `base` content and swaps `c` (and `reporterBar.c`) in `newGame`/on load; the level is chosen in the `newgame` modal (`settings.difficulty`). Bots: `--difficulty easy|normal|hard`.
  - Gentle first days for everyone (CONCEPT.md §4.7, `lookup.ts` `factCheckStarted`/`conflictsStarted`/`rivalStarted`): `exposureRiskOf` is 0 before `factCheckStartTurn` (and such lies never enter `pendingLies`; `counterTargets` skips them), no incidents (`advanceRelations`) or conflict templates (`findNews`, `planRival`) before `conflictStartTurn`, the rival neither plans, prints nor moves readers before `rivalStartTurn[mode]`. Tests run the mechanics on content with all three at day 1 (`tests/sim.test.ts` `content`); the gentle days have their own test on `realContent`. `PublicationReport.building` is the place a story is about (the morning cutscene flies there).
  - Tasks and stars (`tasks.ts`, `tasks.json`, CONCEPT.md §4.8): `assignTasks` (end of `startTurn`, on `taskStartTurn`) gives `taskCount` different tasks of the mode (`TaskDef.mode`, never `twist` ones, never one the town already meets) into `state.tasks` (`TaskState` with `base` for relative checks: debunks, readers, city index). `updateTasks` (in `playTurn` right after `startTurn`, for the day that ended) settles them: `reach` done when `taskProgress(...).holds`, failed after `untilTurn`; `keep` failed when it breaks (`noExposure` by this turn's exposures), done after `untilTurn`; done pays `taskReward` (`reward` × `taskRewardMul`), a failed twist task adds its `penalty` to `state.budgetCut` (an upkeep item of kind `budget`). `TurnReport.tasks`. `state.exposedTotal` counts our exposures; `scoreOf` gives the stars (win, all ordinary tasks done, clean). UI: `tasksNotice` (`renderTasks`, `taskLine`, folded by `settings.tasksOpen`), summary lines, `outcomeStars`; records per mode × difficulty in `ui/records.ts` (`submitRecord` in `endTurn` on a win, `newRecord`, `recordOf` on the mode cards, `starLine`).
  - The mid-game twist (`twists.ts`, `twists.json`, CONCEPT.md §4.9): `advanceTwist` (in `startTurn` after `advanceCity`, before relations) starts one twist of the mode on `twistTurn` (`state.twist`: `untilTurn` = start + `days`; `runningTwist` while `turn < untilTurn` and no result), the governor adds `governorMood` a day, and on `untilTurn` the election picks `electionLeader` (mood vs `electionPivot`) and the governor leaves; the audit gives its `task` (`giveTask`) and ends with it (`settleAudit`). `twistMods` feeds `advanceRelations` (tension fading `peacemakerDecayMul`/`hardlinerDecayMul`, `hardlinerIncidentMul`, no reconciliation under the hardliner, `peacemakerReconcileDrop`) and `exposureRiskOf` (`governorCheckerMul`). `TurnReport.twist` {started, ended}. UI: `twistNotice` (`renderTwist`, icons `ui/ballot|audit|governor`), `twistLines` in the summary, «Мэр: …» in the city events (`mayorName`).
  - Map (`map.ts`): every third tile row/column is a road; lots between roads hold one 2×2 building or `smallPerLot` 1×1 buildings; `x, y` of a building is the top tile of its footprint.
- `src/render/` — PixiJS city (`scene.ts`), purely presentational. It rebuilds the map when the seed changes, swaps building sprites by state, and runs cosmetic resident agents (daily routine over a BFS road graph, leaving with suitcases, protests at the city hall, reactions from `state.lastReactions` after a turn). Cosmetic randomness may use `Math.random`. Zoom is integer in device pixels (crisp pixel art), by default one step closer than the whole-city fit (`defaultLevel`); below ×1 it starts at twice the fit.

  | Difficulty | Destroy: `mixed` / `agitator` | Save: `defender` / `soother` | Save: `bystander` |
  |---|---|---|---|
  | easy | ~48% / ~56% | ~56% / ~53% | ~27% |

  | hard | ~15% / ~22% | ~15% / ~22% | ~8% |
